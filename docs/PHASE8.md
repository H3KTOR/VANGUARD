### Known false-positive / false-negative risks (not hidden)

- Web detectors read access-log fields only: no request bodies, so payloads delivered in POST bodies are invisible (false negatives); legitimately unusual URLs (e.g. a search for “union select”) can match signatures (false positives — widened slightly by percent-decoding in Phase 5).
- Domain/URL IOC matching is blind unless the log format records `Host`.
- IP-based logic (flood, brute force, IOC) is wrong behind a proxy/NAT/CDN unless the log carries the real client address.
- Dedupe is in-memory: a restart can re-raise a finding once.
- Scan-based host detectors cannot see changes that appear and revert between scans (2–10 min).
- `TestPortScanRule` (legacy) is vacuous; coverage of port scanning rests on the new boundary tests.

## Workstream 8C — lab reliability (what changed)

New `lab/run-all.sh`: checks prerequisites (docker, compose, jq, curl, healthy victim), runs each suite independently, judges each **only** on assertion lines it printed (`[✓]`/`[✗]`), treats exit≠0, any ✗, or *zero* assertions as **fail**, writes `lab/results/summary.json` (suite status + every assertion; a no‑jq fallback still records why nothing ran), supports `--only`, `--teardown`, and exits **0 pass / 1 fail / 3 blocked**. Blocked and skipped suites are never counted as passes. **Verified here in its BLOCKED path only** (no Docker): exit 3, valid JSON, all four suites `blocked`. The pass/fail paths have never executed.

Mutated resources (all inside the victim container, restored by the scenarios): `/etc/vanguard-lab/*`, a **copy** of the dpkg status file, a temporary nginx listener on :9999, the victim's SQLite DB, and a container restart. Network: private `172.28.0.0/24`; no external targets. The developer host is not modified. `docker compose down -v` (`--teardown`) removes everything.
